# 🌿 PlantShop — интернет-магазин растений

[![Сборка и тесты](https://github.com/twixkox/OnlineShop/actions/workflows/build.yml/badge.svg)](https://github.com/twixkox/OnlineShop/actions/workflows/build.yml)

Интернет-магазин питомника растений на **ASP.NET Core MVC**. В нём есть:
- каталог с фильтрами по характеристикам растений;
- корзина, которая работает и без регистрации;
- промокоды;
- онлайн-оплата через ЮKassa;
- отзывы и рейтинг товаров;
- письма о заказах;
- личный кабинет и административная панель со сводкой продаж.

**Демо:** http://91.122.60.254:8080/

## Возможности

### Для покупателей
- **Каталог.** Фильтры по цене, освещению, поливу, зимостойкости и наличию, сортировка и постраничный вывод — всё на сервере, поэтому каталог не тормозит при сотнях товаров. Фильтры сохраняются в адресе, так что ссылкой с ними можно поделиться.
- **Характеристики растений.** Высота, освещение, полив, зона морозостойкости (с подсказкой для Ленобласти), период цветения или урожая.
- **Корзина без регистрации.** Гость может собирать корзину, а при входе или регистрации она переносится в аккаунт.
- **Остатки на складе.** Метки «Нет в наличии» и «Осталось 3 шт.»; положить в корзину больше, чем есть, нельзя; при заказе остатки списываются.
- **Промокоды.** Процентная скидка, срок действия, минимальная сумма заказа.
- **Оформление заказа:**
  - имя и телефон подставляются из профиля;
  - дата доставки выбирается в календаре;
  - точку доставки можно отметить на Яндекс.Картах;
  - оплата при получении или онлайн через ЮKassa.
- **Отзывы и рейтинг.** Оценка от 1 до 5 звёзд и текст; средний рейтинг показывается на карточках.
- **Избранное** — сердечко на каждой карточке.
- **Личный кабинет:**
  - фото профиля;
  - личные данные;
  - история заказов с таймлайном статуса;
  - повторная попытка оплаты;
  - смена пароля.
- **Восстановление пароля** по ссылке из письма.
- **Письма.** Подтверждение заказа и уведомление о смене его статуса.

### Для администратора
- **Сводка:**
  - выручка, число заказов и средний чек за 7 или 30 дней, 90 дней или год, со сравнением с прошлым периодом;
  - график выручки;
  - заказы по статусам;
  - хиты продаж и товары, которые заканчиваются.
- **Товары** — CRUD, фото с автоматической миниатюрой 300×300, остатки и характеристики.
- **Категории** — CRUD с изображениями.
- **Заказы** — просмотр, оплата, промокод и смена статуса; покупатель получает письмо о новом статусе.
- **Промокоды** — создание, срок действия, минимальная сумма, включение и выключение.
- **Отзывы** — модерация.
- **Пользователи и роли** — редактирование, смена пароля, назначение ролей.
- **Журнал** — ошибки, предупреждения и запросы прямо в админке: фильтр по дню, уровню и тексту, поиск по коду запроса со страницы ошибки, стек исключения, скачивание файла. На сводке видно, сколько ошибок было за сутки.
- Доступ по ролям: **Admin** — всё, **Manager** — товары, категории, заказы, промокоды и отзывы.

### SEO
- Человекочитаемые адреса `/catalog`, `/catalog/rozy`, `/product/{id}`; старые адреса перенаправляются на новые.
- `sitemap.xml`, `robots.txt`, теги Open Graph для красивых превью в мессенджерах, canonical-ссылки.

## Дизайн и анимации
- Собственная дизайн-система поверх Bootstrap 5: лесной зелёный, кремовый фон и терракотовый акцент, шрифты **Lora** и **Manrope**.
- Адаптивная вёрстка; на телефоне фильтры выезжают боковой панелью.
- Анимации:
  - появление блоков при прокрутке;
  - «полёт» товара в корзину;
  - пульс сердечка избранного;
  - увеличение фото товара под курсором;
  - рисующаяся галочка и конфетти после заказа;
  - выезжающие столбцы графика в сводке.
- Учитывается системная настройка «уменьшить движение» (`prefers-reduced-motion`).

## Безопасность
- Административная панель закрыта `[Authorize]` с разграничением по ролям.
- Идентификатор пользователя берётся только из авторизации, а не из запроса. Гостевая корзина привязана к случайному токену в cookie, поэтому подставить чужой id нельзя.
- Пользователь видит только свои заказы.
- Формы защищены от CSRF.
- Платёж подтверждается только запросом к API ЮKassa: данным из уведомления сайт не доверяет.
- При восстановлении пароля нельзя узнать, зарегистрирован ли email.
- Секреты (JWT-ключ API, пароль SMTP, ключ ЮKassa) не хранятся в репозитории и задаются переменными окружения.

## Технологии

### Backend
- ASP.NET Core MVC (.NET 10)
- ASP.NET Core Web API — отдельный проект для REST API (JWT, Swagger)
- Entity Framework Core (Code First, миграции), SQL Server
- ASP.NET Core Identity — аутентификация, роли, восстановление пароля
- SixLabors.ImageSharp — миниатюры товаров и аватары
- ЮKassa REST API — онлайн-оплата
- SMTP (System.Net.Mail) — письма
- Serilog — структурированный журнал (JSON), ротация по дням, отдельный файл ошибок

### Frontend
- Bootstrap 5 + Bootstrap Icons
- JavaScript без фреймворков: AJAX-корзина и избранное, анимации, форматирование телефона
- Yandex.Maps API — выбор адреса доставки

### Инфраструктура
- xUnit — модульные тесты
- GitHub Actions — сборка и тесты на каждый PR
- Docker и Docker Compose

## Установка и запуск

### Через Docker (проще всего)
```bash
git clone https://github.com/twixkox/OnlineShop.git
cd OnlineShop
docker compose up --build
```
Сайт откроется на http://localhost:8080. Вместе с ним поднимется SQL Server, а загруженные фото сохранятся в томе `uploads`.

### Локально
1. Установите [.NET 10 SDK](https://dotnet.microsoft.com/download) и SQL Server (подойдёт LocalDB).
2. Проверьте строку подключения в `OnlineShopWebApp/appsettings.json`:
   ```json
   "ConnectionStrings": {
     "OnlineShop": "Server=(localdb)\\MSSQLLocalDB;Database=OnlineShop;Trusted_Connection=True;"
   }
   ```
3. Запустите сайт:
   ```bash
   cd OnlineShopWebApp
   dotnet run
   ```
   Миграции применятся автоматически. В базу добавятся тестовые категории, товары с характеристиками и промокоды `SPRING10` и `GARDEN15`.
4. Откройте http://localhost:5078.

### Web API
Для API нужен секретный ключ JWT длиной не меньше 32 символов. Для локальной разработки он уже лежит в `appsettings.Development.json`; на сервере задайте переменную окружения `Jwt__Key`.

## Настройка почты и оплаты

Всё задаётся в `appsettings.json` или переменными окружения. Секреты лучше хранить именно в переменных окружения, например `Smtp__Password`, `YooKassa__SecretKey`.

### Почта (SMTP)
```json
"Smtp": {
  "Host": "smtp.yandex.ru",
  "Port": 587,
  "EnableSsl": true,
  "UserName": "shop@example.ru",
  "Password": "пароль приложения",
  "From": "shop@example.ru",
  "ManagerEmail": "manager@example.ru"
}
```
Пока `Host` и `From` пусты, письма не отправляются, а сайт работает как обычно. Для разработки задайте `"PickupDirectory": "App_Data/mail"` — письма будут сохраняться в эту папку файлами `.eml` (в `appsettings.Development.json` это уже включено). В журнал тексты писем не попадают. `ManagerEmail` — адрес, на который приходят уведомления о новых заказах.

### Онлайн-оплата (ЮKassa)
```json
"YooKassa": {
  "ShopId": "123456",
  "SecretKey": "test_..."
}
```
1. Возьмите `ShopId` и секретный ключ в [личном кабинете ЮKassa](https://yookassa.ru/my). Для проверки подойдёт тестовый магазин.
2. В разделе «HTTP-уведомления» укажите адрес `https://ваш-сайт/payment/yookassa` и включите событие `payment.succeeded`.
3. Пока ключи не заданы, на странице оформления доступна только оплата при получении.

## Журнал

Журнал пишет Serilog; все настройки — в разделе `Serilog` файла `appsettings.json`, менять их можно без пересборки.

| Файл | Что внутри | Хранится |
|---|---|---|
| `Logs/app-ГГГГММДД.log` | все записи за день (запросы, действия, ошибки) | 30 дней |
| `Logs/errors-ГГГГММ.log` | только предупреждения и ошибки | 12 месяцев |

- **Формат:** одна запись на строку в формате JSON (Compact Log Event Format), поэтому журнал можно читать программно.
- **Размер файла** ограничен 50 МБ; если его не хватает, создаётся следующая часть файла того же дня.
- **В каждой записи** есть код запроса (`TraceId`), Id пользователя и IP. Код запроса показывается покупателю на странице ошибки, и по нему администратор находит все записи этого запроса в разделе «Журнал».
- **Персональные данные** маскируются: `an***@mail.ru`, `***-**-34`. Тексты писем, токены и пароли в журнал не попадают.
- **Каждый запрос пишется одной строкой.** Статические файлы (картинки, стили, скрипты) и служебные сообщения уровня Debug в журнал продакшена не попадают.

Web API пишет такой же журнал в `Logs/api-ГГГГММДД.log`.

## Тесты и CI
```bash
dotnet test OnlineShop.Tests
```
Тесты покрывают корзину (остатки и перенос гостевой корзины), фильтры, сортировку и страницы каталога, списание остатков, отзывы, промокоды, формирование запроса к ЮKassa, защиту гостевой cookie, маскировку персональных данных и чтение журнала.

GitHub Actions (`.github/workflows/build.yml`) собирает решение и запускает тесты на каждый пулл-реквест и push в `master`.
